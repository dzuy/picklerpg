# Private match chat

Implemented locally on `codex/persistent-match-chat`, October 3, 2026. Not migrated or deployed to production. Requires `supabase/migrations/20261003120000_player_chat.sql` before deploying the server/client.

## Player experience

The bottom-right chat icon opens a sheet covering the bottom 60% of the gameplay area. Gameplay, including automatic play, continues. The sheet can be closed with its close button, Escape, a downward swipe on the header, or a tap on exposed gameplay. Opening the sheet does not summon the keyboard; tapping the input does. The sheet stays in place as the keyboard opens, with only the composer raised above the keyboard. Physical-device iOS keyboard/safe-area verification remains required.

The conversation looks like a text exchange, with your messages on the right, the opponent's on the left, dates/times and older-history loading. The 18 existing emoji shortcuts send ordinary conversation messages. Text allows 500 Unicode code points; on-court speech bubbles show at most 60, last five seconds, and open the conversation when tapped. No profanity filtering applies to private messages. A future optional app preference may filter their display; it is not implemented. Public names/catchphrases and directory text retain their existing filtering policy.

Each conversation belongs to exactly two account IDs. Character selection, team composition, home/away order and rematches do not change its identity. The same history is accessible from any match between those accounts. There is no inbox or out-of-match chat entry point yet. Device-local practice retains its existing match-scoped local storage and 60-message cap, using the same presentation without claiming to be a private exchange with another person.

The sheet uses a dark palette. Its header shows the existing account-pair rivalry win/loss record from the viewer’s perspective (or an explicit unavailable state). Mute, Block, Report and Contact live in a pop-up menu opened by a small red flag to the left of the input. Flag, input and send button share the bottom row, including above the keyboard. Mute is a per-account, per-conversation server preference that suppresses bubbles/sounds but keeps readable history. The existing device-wide bubble mute remains in game settings. Block uses the existing symmetric contact restriction, hides history, disables sending, and prevents new invitations/nudges. Unblock reverses only your own block. Reports can include one selected opponent message, or the last ten opponent messages if none is selected; the report dialog states exactly what will be shared.

## Persistence and authorization

`player_conversations` has one unique sorted account pair. `player_messages` stores sender, originating match/version, text, time and a UUID retry key. It survives removal of a match; deleting either account removes the conversation. `player_chat_preferences` stores the participant's mute choice. The migration copies existing match reactions into pair history; already censored legacy text cannot be recovered. Legacy tables/RPCs remain for compatibility but the updated API writes only the new store.

All three tables have RLS and no direct client or service-role table grants. The server uses service-role-only RPCs that derive the pair from a match and explicitly verify the authenticated actor. Pending matches without a second account fail closed. No general inbox, public conversation listing or administrator history endpoint is provided. This is application-level privacy, not end-to-end encryption: database operators retain infrastructure access. Only reported evidence is exposed through the existing restricted `player_reports` review queue.

- `GET /api/matches/:id/trash-talk`: latest 50 messages, chronological, plus conversation metadata and current-match replay messages. Older pages use `beforeTime` and `beforeId`, an exclusive compound cursor.
- `POST /api/matches/:id/trash-talk`: `{id, text}`. Retry keys are pair-scoped; conflicting content is rejected. A pair-row lock serializes sends from concurrent matches. The existing three-second per-sender cooldown applies across all matches in the pair, with the existing HTTP rate limit retained.
- `POST /api/matches/:id/chat-preferences`: `{muted}`; authenticated participant only.
- Existing safety endpoints derive the opponent from the match. `player_chat_report_evidence` permits only that participant's opponent messages, including prior matches and evidence after a block. Evidence is copied into the report, so reviewers do not need access to unrelated private history.

Chat never changes game versions, turn ownership, notification clocks or checkpoints. Replay uses messages from the current match only, projected onto that match's home/away player positions. The client clears account/match state and rejects stale responses; chat text is not stored in recent-message preferences or sent to analytics. The chat surface remains excluded from session recording by the existing `.trash-talk` privacy rule.

## Main-game integration verification

The main game uses this component directly: `src/multiplayer/remote-main.ts` mounts it in the actual court and supplies the authenticated session, match and rivalry; `src/main.ts` reuses it for device-local practice. The production multiplayer handler wires the same chat and safety services. Match changes clear the previous opponent label, message DOM cache and safety menu while the next history loads.

Run `npm run preview:chat` for the complete game at `http://127.0.0.1:5194/preview`. This extends the existing playable rivalry environment; it uses the real renderer, match engine, routes, chat/safety services and migrated PostgreSQL schema. Only authentication and the Supabase transport boundary are replaced for disposable local accounts. No production credentials or data are used. Open the Alex and Ryan links in separate tabs, or the second-match link to inspect persistent history. Stopping the preview deletes its temporary database. The standalone layout preview remains at port 5189.

October 3 integration verification: messages sent from both main-game accounts appeared in the other participant's history and carried into a different match. Both accounts completed an automatic-play match with chat open; the pair record updated afterward. `tests/player-chat-game.test.ts` exercises real game/chat HTTP routes against PostgreSQL, including turn progression, persisted messages, mute across games, block/unblock and saved report evidence. Eight focused integration/regression tests passed. Production migration/deployment and physical-iPhone verification remain pending.
